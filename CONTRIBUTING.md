# Разработка

Перед изменениями прочитайте [AGENTS.md](AGENTS.md), [ТЗ](TECH_SPEC.md) и
[архитектуру](docs/architecture.md). README описывает реализованные возможности;
ТЗ включает также будущие этапы. Новые продуктовые решения сначала согласуются.

## Подготовка

Нужны Python 3.12+, uv, Docker и Docker Compose 2.24+. Установите зависимости:

```bash
uv sync --frozen --extra dev
docker compose up -d --wait db
```

Для локального бота настройте `.env` по `.env.example`, примените миграции и выполните
`uv run setlist-bot --check` с `DATABASE_URL` рабочей локальной базы. Эта проверка не
обращается к Telegram. Не запускайте второй polling-процесс с токеном работающего бота.

## Проверки во время разработки

Для небольших изменений запускайте только тесты затронутого поведения и связанные
проверки линтера/типов. Исправление ошибки сопровождайте воспроизводящим её тестом,
если это проверяет поведение, а не повторяет реализацию. Для документации достаточно
проверки diff, для Compose — проверки конфигурации и запуска затронутых сервисов.
Не повторяйте успешные проверки без новых изменений или причин для сомнений.

Изменения прав, приватности, миграций и целостности данных требуют связанных
интеграционных проверок сразу. Полный набор ниже обязателен перед обновлением
основного сервера; GitHub Actions также выполняет его при push/PR.

Ручная проверка новых функций проходит на отдельном Telegram-боте и базе
по [инструкции песочницы](docs/operations.md#тестовый-бот-в-среде-разработки).

## Полные проверки перед выпуском

Интеграционные тесты требуют отдельную PostgreSQL-базу. Создайте её один раз:

```bash
docker compose exec -T db createdb -U setlist setlist_test
```

Затем:

```bash
export TEST_DATABASE_URL=postgresql+asyncpg://setlist:setlist@localhost:5432/setlist_test
uv lock --check
uv run ruff check src tests migrations
uv run ruff format --check src tests migrations
uv run mypy src
uv run pytest -q
git diff --check
```

Тесты очищают таблицы и откатывают миграции только в базе с суффиксом `_test`.
Тесты Telegram работают через подменённый сеанс, не используют настоящий токен и
не отправляют сообщения. GitHub Actions повторяет проверки на Python 3.12/PostgreSQL 17.
В TSV-примерах сохраняйте завершающие табуляции: они обозначают пустые ячейки.
Для этих файлов проверка пробелов в конце строки настроена в `.gitattributes`.

## Изменения

- Домен и прикладные сценарии не зависят от Telegram и SQLAlchemy.
- Проверяйте права, изоляцию коллективов, приватность черновиков и конфликты версий.
- Изменения схемы сопровождаются Alembic-миграцией; исторические снимки сохраняются.
- Новую публичную команду добавляйте в обработчик, RU/EN-справку и реестр
  `src/setlist_bot/transport/commands.py`. Внутренние callback-действия в меню не включаются.
- Описывайте изменения поведения в README/CHANGELOG; согласованные требования — в ТЗ.
- Добавляйте проверки поведения, особенно прав доступа, целостности и конкурирующих правок.

Перед коммитом проверьте `git diff --cached`: в него должны входить исходники,
конфигурация без секретов, миграции, тесты и документация. `.env`, токены, дампы,
резервные копии, журналы и локальные кэши не публикуются.

Коммиты и push сохраняют исходники. Обновление работающего бота выполняется отдельно
по [инструкции эксплуатации](docs/operations.md).

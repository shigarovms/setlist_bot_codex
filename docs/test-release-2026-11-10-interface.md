# Тестовый выпуск интерфейса setListBot

Ветка `feature/web-admin`. Вершина Alembic `c91a72e6b304`. Новых миграций и переменных
окружения нет. Обновлятор выдаёт календарю чтение роли членства и срока приглашения,
Mini App — чтение минимального набора полей приглашения. Длительность выступления
сохраняет polling-воркер с обычными правами через существующие Confirmation и outbox.

## Обновление песочницы

Если коммиты ещё локальные, из рабочей папки разработчика опубликовать ветку:

```bash
git push origin feature/web-admin
```

Затем выполнить команды на VPS. Перед запуском убедиться, что тестовый токен
используется только серверным экземпляром.

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  test -z "$(git status --porcelain)"
  git rev-parse HEAD
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  bash scripts/update-sandbox-admin.sh server
  docker exec setlist-sandbox-bot-1 .venv/bin/setlist-bot --check
  docker logs --since 3m --tail 60 setlist-sandbox-bot-1
)
```

Сохранить SHA из вывода `git rev-parse HEAD` перед обновлением. Штатный скрипт собирает образ, резервирует серверную
тестовую базу, обновляет права и сохраняет дополнительные настройки Compose для
админки, Mini App, календаря и HTTPS-прокси. Проверить `Command menus verified`,
запуск polling `@botToPract696_bot` и доступность HTTP-сервисов по HTTPS.
Основной бот и его база остаются вне процедуры.

## Ручная проверка

1. Открыть меню лички и общего чата в RU и EN. Проверить дополнительное меню у
   администратора Telegram-чата, шесть тем `/help`, старые команды и `/cancel`.
2. Одним аккаунтом проверить два коллектива с разными правами. Без приглашения
   участник видит репертуар. Выступление отсутствует в списке, старой кнопке,
   Mini App и существующей календарной ленте. После приглашения оно появляется.
   Проверить сессионщика, отмену, перенос, удаление и историю своего приглашения.
3. Пустой список открывается в редакторе без кнопки утверждения. Непустой общий
   список можно утвердить, после утверждения первое действие — PDF. Проверить
   запрос участника, подтверждение возврата в работу и отдельную публикацию
   личного варианта. В «Опциях» проверить, к чему относится каждое изменение.
4. Открыть предварительный состав, изменить кандидата, нажать «Назад» и продолжить
   редактирование. Сохранить состав без приглашений, проверить занятость, сверить
   число получателей и отправить. При пересечении проверить явный выбор обеих
   сторон. Изменить порядок постоянных кандидатов и исключить одного из подбора.
5. На телефоне проверить светлую и тёмную тему Mini App, узкий экран, перетаскивание,
   повторы, пустые подписи пауз, Undo и индикатор автосохранения. При отключённой
   сети повторить сохранение после восстановления соединения. В истории проверить
   список, предпросмотр и возврат к прежнему вводу. Администратором задать `45`
   и `1:15`, обновить редактор и проверить план. Участником проверить, что ввод
   плана скрыт. Изменение средней паузы не должно переписывать существующие списки.
6. Первым пользователем пройти профиль обычными сообщениями, отложить и продолжить,
   уточнить «звукорежиссёр» и сохранить свою роль. В сохранённом профиле поменять
   только город, проверить возврат к карточке и отказ устаревшей кнопки.
7. В интернет-отборе проверить ремиксы, Live, галочки и длительности. Снять и
   восстановить выбор на нескольких страницах, открыть фильтр, вернуться из
   предпросмотра. Проверить, что каталог пополняется только после итоговой кнопки
   с числом новых песен.

## Откат

В песочнице переключить чистую рабочую папку на сохранённый SHA и повторно запустить
штатный обновлятор:

```bash
cd /opt/setlist_bot_sandbox
rollback_sha='ВСТАВЬТЕ_СОХРАНЁННЫЙ_SHA'
test -z "$(git status --porcelain)" &&
  git switch --detach "$rollback_sha" &&
  bash scripts/update-sandbox-admin.sh server
```

Схема при этом остаётся `c91a72e6b304`. Сохранённые профили, составы, длительности
и черновики используют прежние таблицы. Ссылки календаря сохраняются, однако
возврат к старому коду вернёт прежнюю видимость по членству. Учитывать это при
решении об откате. Перед остановкой нового воркера дождаться обработки очереди
изменения длительности: старый код не обрабатывает этот вид заявки. Проверить
результаты запросов в тестовом интерфейсе. Выданные дополнительные права
чтения при необходимости отозвать отдельно после остановки новых HTTP-сервисов.

## Обновление на VPS

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  git status --short
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  bash scripts/update-sandbox-admin.sh server
)
```

Скрипт собирает образ, останавливает тестовые процессы, сохраняет свежую копию
серверной тестовой БД, выполняет миграцию, проверяет схему/health и запускает сервисы.
Основные bot/БД не обновляются. Поскольку схема sandbox стала новее, раздел основного
контура в общей админке может быть недоступен до отдельного согласованного основного
выпуска; основной Telegram-бот продолжает работать.

## Что проверять

1. **Навигация коллектива.** Под переносом чата — «◀️ Все мои коллективы». Кнопка
   есть и у обычного участника без права переноса. Каталог снова из пяти столбцов:
   редактирование через название песни; карандаши и формы Mini App сохраняются.
2. **Добавление песен.** `/add_new_songs Новая песня 03:20`; многострочный список
   `Первая 03:20` / `Название 12:34 02:10`. Последнее отдельное ММ:СС — время,
   внутреннее `12:34` остаётся в названии. `03:75` не сохраняется. Сверьте TSV,
   CSV и дополнительные поля через два пробела — прежний порядок сохраняется.
3. **Поиск Mini App.** На телефоне после входа в поиск поле очищается и остаётся
   полностью видимым с отступом от верхнего края. На компьютере первый клик очищает
   старый запрос, прокручивает и сразу даёт печатать; второй клик не требуется.
4. **Профиль.** `/start` → «👤 Мой профиль». Первый вопрос содержит согласованный
   текст про имя/представление со сцены; это одно поле. Затем роли, город, готовность
   к подменам/выездам, короткое «О себе». В текстовых вопросах `-` оставляет поле
   пустым, `=` сохраняет текущее значение при редактировании; `/cancel` отменяет анкету. Сохранение только после общего подтверждения.
   Проверьте повторное подтверждение, чужой ответ и старое сообщение вопроса.
5. **Имя.** После сохранения профиля новое сообщение от Telegram не заменяет имя
   исходным именем аккаунта. Выбранное имя отображается коллегам; старые имена
   членств остаются в БД как резерв, до заполнения профиля работают прежние правила.
6. **Профессиональные роли.** Введите `басист, bass player, FOH, MON`: бас не дублируется.
   «Звукарь»/«звук» — общий термин, бот попросит назвать позиции; FOH не означает MON.
   Неоднозначные «фон», «TM» требуют полного названия. Пользовательские роли допустимы.
7. **Постоянная команда.** `/team` либо `/groups` → коллектив → «Составы [название]»:
   «Участники коллектива», «Знакомые исполнители», «Составы», «Назад».
   В участниках добавьте несколько строк `Роль @ник` или `Роль: TelegramID`.
   Неизвестный человек не оставляет частично сохранённый список; перешлите приглашение
   открыть бота и нажать /start. Можно изменить назначение/приоритет и убрать его
   из постоянных с подтверждением. Сами выступления и приглашения не отменяются.
8. **Составы.** Старые выше новых; переименование не меняет место. Состав задаёт роли,
   исполнители берутся из постоянной команды коллектива. Число приоритета меньше —
   кандидат раньше. При двух одинаковых ролях подставляются разные основные люди;
   если второго нет, позиция остаётся свободной. Внизу списка — создание и назад.
9. **Подготовка выступления.** Выберите состав, проверьте подставленных людей и
   занятость, затем отправьте приглашения. Сам выбор состава приглашений не отправляет.
   Замена основного в команде действует на новые применения состава, не меняет
   существующие назначения. Участие подтверждается по прежним правилам.
10. **Подмены.** Постоянному FOH укажите в личном профиле FOH + MON + звуковой техник
    и готовность к подменам. Он должен появиться кандидатом на MON в том же коллективе.
    Человек только с FOH не появляется на MON автоматически. Люди вне знакомых/команды
    этого коллектива не раскрываются. «Не предлагать» и занятость продолжают учитываться.

## Данные и откат

Миграция добавляет профиль/версию пользователя, признаки постоянного назначения,
приоритет/версию контакта и время создания состава. Прежние пользователи получают
пустую анкету. Основные исполнители, записанные в сохранённых составах, становятся
постоянными; исходные JSON и существующие бронирования не переписываются.
Время создания прежних составов восстанавливается из аудита, где он есть. При отсутствии
истории используется время миграции с устойчивым порядком по ID — точную старую
хронологию восстановить нельзя.

Назначение в команду не выдаёт членство или административные права. Глобальные навыки
заявляет сам человек; они расширяют подбор только среди уже известных коллективу
исполнителей. Внешние календари/аккаунты для занятости не подключаются.

Новые данные защищены ограничениями PostgreSQL, версиями и транзакциями. Прямой
`downgrade` при заполненных профилях/постоянных назначениях запрещён. Не используйте
`git reset --hard`, восстановление дампа или откат схемы наугад; для возврата нужна
согласованная процедура по резервной копии именно серверного тестового контура.

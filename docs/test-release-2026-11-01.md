## В выпуске

1. Article по умолчанию с сохранением аудированного ручного выбора mono.
2. Создание выступления одной строкой: дата, площадка/название, длительность, тип,
   город и примечания, разделённые двумя пробелами или точкой с пробелом. Три
   согласованных примера, подтверждение всех полей и повтор ввода.
3. Один список для копирования после «Ввести списком»; выбор способа не дублирует его.
4. Редактор первым в личке и группе. Из группы также переход в личку с тем же
   выступлением и выбором способов. Reply-клавиатура песен остаётся только в личке.
5. Main Mini App из общей ссылки создаёт отдельную сессию/черновик каждому участнику.
   Права, привязка чата, эпоха удаления и подпись start_param проверяются сервером.
6. Автосохранение после короткой паузы, сериализация запросов и защита от позднего
   ответа сервера. Оно не публикует вариант. «Предложить в группу и закрыть» ставит
   обычное предложение в очередь и ждёт подтверждения доставки. Крестик не публикует.

## Команды VPS

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  git log -2 --oneline
  bash scripts/update-sandbox-admin.sh server
  python3 scripts/setup-sandbox-miniapp.py
)
```

Дождитесь завершения обоих скриптов до проверки кнопок. Обновление сохраняет
резервную копию своей серверной тестовой БД, применяет схему `f2d7c614a083` и собирает
общий образ. Повторный установщик **обязателен**: публичной SQL-роли добавлены права
на создание личной сессии, обычного предложения и outbox. Токен Bot API в Mini App
по-прежнему не передаётся. Тексты и payload других сообщений очереди читать нельзя;
для подтверждения доставки доступны только столбцы состояния. Админка остаётся за SSH.

Сеть уже подключённой production-админки сохраняется; её основной раздел требует
совместимой версии схемы при отдельном выпуске production. Polling основного бота
и его схема не меняются этими командами.

## Проверка в Telegram

1. `/concert` → отправьте каждый из трёх примеров из инструкции. Проверьте все поля,
   включая 15 декабря, Питер → Санкт-Петербург, Корпорат и 85мин. Переставьте параметры.
   До подтверждения выступление не создаётся. «Изменить данные» позволяет повторить.
2. Новое выступление → Article. Через настройки переключите стиль на mono и обратно.
3. «Изменить» → сначала редактор, затем списком, затем песнями. При выборе списка
   ровно одно сообщение с длительностью/копируемым списком и `/cancel`.
4. В группе «Предложить свой вариант» → первым редактор. Откройте двумя участниками:
   порядок/повторы/паузы у каждого свои. Проверьте также переход в личку на то же
   выступление, даже если там раньше был выбран другой коллектив.
5. Измените список в Mini App, дождитесь «Сохранено», закройте крестиком и снова
   откройте: черновик сохранён, предложений в группе не появилось.
6. «Предложить в группу и закрыть» → одно предложение с именем автора и штатной
   кнопкой применения. Окно закрывается после доставки. Общий список сам не заменяется.
7. Повторное нажатие/проверка отправки не создаёт копию. Если связь оборвалась,
   остаются личный ввод и возможность повторить. При конфликте с другим устройством
   показан актуальный черновик; поздний ответ не затирает новый ввод.
8. Старые команды, Reply-набор песен, утверждение и экспорт работают как прежде.

Полные инструкции: [ввод выступления](performance-input.md), [Mini App](miniapp-editor.md).

# Поиск песен в интернете — тестовый контур

## Проверка пользователем

После создания коллектива бот сразу предлагает все способы пополнения каталога:
«🌐 Найти песни в интернете» (первым), ручной ввод, Google Sheets / Excel и таблицу
Telegram. Это работает и для `/group Название`, и для пошаговой регистрации.
Поиск начинается вопросом «Искать коллектив „Название“?» с кнопками Да / Ввести
вручную / Отмена. В общем чате уточнение и ожидание проходят там же; готовый отбор
приходит запросившему в личку. Остальные способы открывают инструкции `/add_new_songs`.

1. Откройте `/catalog` в нужном коллективе под его администратором.
2. Нажмите «🌐 Найти песни в интернете», подтвердите название или выберите ручной ввод.
3. При ручном вводе ответьте именем исполнителя или ссылкой на страницу исполнителя
   Apple Music, MusicBrainz, Spotify либо Яндекс Музыки. Последние две используются
   для определения имени, а не как обещание доступа к их закрытым API.
4. Дождитесь вариантов и подтвердите исполнителя по примерам песен. При отсутствии
   рейтинга они явно называются примерами, а не популярными песнями.
5. Поиск может занять 20–30 минут; другие команды доступны. О завершении сообщит бот.
6. Когда результат готов, бот отправит таблицу запросившему в личку и уведомит группу.
   Если личка недоступна, даст кнопку перехода к сохранённым результатам.
   В таблице по алфавиту снимите ✅ с ненужных песен: ⬜ и зачёркивание. Повторное нажатие
   возвращает песню. По 20 строк на странице, выбор общий для всех страниц.
   У каждой строки есть длительность; неизвестная явно отмечена. Ремиксы по умолчанию
   исключены. Если есть обычная и Live-версия одной песни, выбрана Live, обычная
   исключена; любое исключение можно отменить. Это первоначальный выбор только новых
   отборов: уже начатая сессия и ручные нажатия при обновлении не сбрасываются.
7. «Продолжить» показывает итоговый состав с длительностями и доступным BPM.
   Только «Добавить в каталог» сохраняет результат. «Назад» позволяет изменить отбор.
8. Существующие песни не перезаписываются. Для неизвестной длительности будет
   отдельный ForceReply-вопрос; можно исключить такую песню. Отмена этого вопроса
   через `/cancel` возвращает отбор. Отмена поиска не меняет сохранённый каталог.
9. После импорта доступны три инструкции: ручной ввод, Google Sheets/Excel и Article.

BPM — опубликованные оценки справочников, а не измерение полного аудио. Несогласующиеся
значения остаются пустыми. Разные версии с одинаковым названием получают видимый
суффикс длительности перед окончательным подтверждением. Полнота дискографии зависит
от источников; неизвестные треки можно добавить вручную.

В первой таблице сохраняется исходное `(feat. …)`. В итоговом предпросмотре и каталоге
этот кредит удаляется. Пометка `(Live)` тоже удаляется, если очищенное название не
совпадает с другой выбранной песней, существующим названием или алиасом каталога.
Иначе Live сохраняется для различения версий. `(Remix)` сохраняется, если пользователь
включил эту песню. Дубликаты проверяет штатный Importer по сохраняемому названию;
существующие песни, алиасы и исторические сет-листы не переименовываются.

## Устройство и ограничения

- `application/music_search.py` отвечает за права, личный отбор и передачу в Importer.
- `infrastructure/music_sources.py`: Apple Music/iTunes, MusicBrainz, SongBPM, Tunebat.
  Каждый запрос имеет таймаут, ограничение ответа 3 MB и фиксированный список хостов.
  Переходы на произвольные URL/редиректы, скачивание аудио и чтение локальных файлов запрещены.
- `infrastructure/music_worker.py`: одна очередь запросов на процесс, минимум 2 секунды
  между запросами. Lease 90 секунд, проверка прав до внешнего запроса, повтор временного
  сбоя до 3 попыток с учётом Retry-After, затем частичный результат. Сетевые запросы
  выполняются без удержания подключения/блокировки PostgreSQL.
- Шаги хранятся в `music_searches`; сессия живёт 48 часов. После 40 минут собственно
  сбора возвращается доступная часть. Не более одного незавершённого поиска на пользователя.
- Результаты — до 500 позиций, исходные данные — до 4000 строк, до 100 релизов,
  до 100 страниц SongBPM. Индексы ограничивают проверку очереди и уборку по сроку.
- `music_cache` хранит только публичные результаты на 24 часа. Исключения пользователя
  и введённые вручную длительности в общий кэш не попадают. Завершённые сессии и кэш
  удаляются штатной уборкой по сроку.
- Изменения выбора объединяются существующим outbox. Article редактируется через
  editMessageText.rich_message: новая таблица только текущей страницы, в том же сообщении.
  Явный отказ Article включает текст с кнопками; сетевой таймаут не создаёт копию.
- Права проверяются на входе, при каждом действии, при доставке и при сохранении.
  Устаревший финальный токен, чужая сессия, смена жизненного цикла группы или роли
  не разрешают импорт. История сет-листов и личные черновики не затрагиваются.
- Сайты могут менять HTML и ограничивать запросы. Недоступность одного источника
  не означает отсутствия песен; бот сообщает о неполном результате.

## Запуск и проверки

Зависимости прежние; дополнительных ключей API не требуется. Нужен HTTPS-доступ к
`itunes.apple.com`, `musicbrainz.org`, `songbpm.com`, `tunebat.com`; для ссылок на
исполнителей — `open.spotify.com`, `music.yandex.ru`, `music.yandex.com`.

Сначала сохраните резервную копию **своей тестовой** БД. Миграция:

```bash
DATABASE_URL=postgresql+asyncpg://setlist:setlist@localhost:5433/setlist_sandbox \
  .venv/bin/alembic upgrade head
```

В Compose вместо этой команды используйте свой штатный сервис `migrate`.
Требуемая схема текущего выпуска `a82cd901be45`. Откат миграции запрещён при незавершённом отборе,
чтобы не потерять решение пользователя. Тестовые данные не переносятся в production.

Целевые проверки, только на отдельной `_test`-базе:

```bash
TEST_DATABASE_URL=postgresql+asyncpg://setlist:setlist@localhost:5433/setlist_test \
  .venv/bin/pytest -q tests/test_music_sources.py tests/test_music_search.py \
  tests/test_music_worker.py tests/test_music_transport.py tests/test_catalog_articles.py
```

После миграции запустите **единственный** тестовый polling. При переносе из VPS
в облако сначала остановите только серверный тестовый сервис `bot`. Production
и серверная админка не обновляются этим действием. Базы остаются независимыми.

Перед будущим обновлением основного контура нужен полный набор проверок и штатная
репетиция миграции на копии основной базы. Этот документ не является командой
развёртывания на основном сервере.

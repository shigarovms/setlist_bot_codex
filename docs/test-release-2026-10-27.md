# Проверка тестового выпуска — 27 октября 2026

Цель — @botToPract696_bot, отдельные Compose-проект и база setlist_sandbox.
Эта инструкция описывает обкатку перед выпуском. Публикация кода в GitHub main
и обновление основного @setListDuration_bot выполняются отдельными шагами.
Автотесты запускаются исключительно на отдельной setlist_test, не на базе песочницы.

## Сценарии ручной проверки

1. `/register Имя` в чате существующего коллектива. Имя меняется, владелец остаётся
   владельцем. В другом коллективе пользователь может указать другое имя.
2. `/members` у владельца: назначить второго принятого участника администратором,
   подтвердить. Он может утверждать/открывать списки, но не назначать/снимать администраторов.
   Снять дополнительные права владельцем, членство и имя должны остаться.
3. В личке предложить вариант и опубликовать. В группе применить: тот же список
   должен сменить заголовок/версию/кнопки. Повтор кнопки не применяет его снова.
   Если общий список изменился после публикации, предложение должно показать конфликт.
4. У мероприятия задать длительность 100 минут. Шапка: `Пауза: 5сек · Выступаем: 100мин`.
5. В наборе кнопками добавить песню, затем паузу `3`: это 3 минуты. «Удалить последнюю»
   должна удалить эту паузу. Проверить `3сек`, `00:00:03` и `2:30`.
6. Список из 10 песен и нескольких пауз: номера песен 01…10, паузы xx.
   При 9 песнях — 1…9, паузы x. Проверить текст и оба PDF (в том числе транслитерацию).
7. `/remove` и `/move` без аргументов: выбрать паузу кнопкой, удалить/переместить.
   В текстовом `/remove 2` удаляется вторая песня, не вторая строка с паузой.
8. Утвердить вторым администратором: подпись его имени и версии, галочка у концерта.
   После смены имени подпись старого одобрения остаётся прежней. После возврата
   в редактирование галочка исчезает при открытии `/concerts`.
9. Проверить порядок опций, появление «Варианты» только при наличии предложений,
   отсутствие административных действий у обычного участника.
10. «Новый концерт»: понятный ForceReply, /cancel в тексте, нет отдельного сообщения
    «Отмена». Проверить отмену и повторный ввод, чужой ответ не должен менять диалог.
11. Открыть несколько меню: прежняя навигационная панель убирается; одобренные
    и актуальные рабочие карточки не удаляются автоматически.
12. «Прибраться в чате»: подтверждение и отмена. После подтверждения известные
    доступные сообщения, включая сет-листы, удаляются. `/concerts`, каталог, личный
    черновик и история остаются в базе и снова открываются командами.
13. `/reminders` администратором: включить/отключить; участнику изменение запрещено.
    Напоминания на завтра распределяются в 14–15 по Москве. Часы и повторный запуск
    автоматически проверяются тестами с заданным временем, без ожидания суток.
14. Меню начинается support, start, concerts, help. RU/EN-справка объясняет новый вход.

## Ограничения уборки

Нет журнала всех отправленных сообщений. Используются ссылки существующих карточек,
запросов и одной текущей панели навигации на пользователя в чате. Старые сообщения,
связь с которыми уже утрачена, найти через Bot API нельзя. Telegram проверяет срок
и разрешения на удаление; отказ удаления не прерывает работу бота.

## Техническая проверка перед запуском

- Полный pytest на PostgreSQL 17, затем Ruff, форматирование, mypy и uv lock --check.
- Сборка Python 3.12 образа, импорт планировщика и проверка Europe/Moscow.
- Резервная копия setlist_sandbox и проверка pg_restore --list.
- Только один polling-процесс с тестовым токеном; перед стартом проверяется ID 1110437563.
- Alembic head: f8129a4b6c30. Миграция сохраняет существующие имена и роли, определяет
  прежнего единственного администратора как владельца и дополняет подписи одобрений.
  Неоднозначность нескольких прежних администраторов приводит к отказу миграции,
  а не случайному выбору владельца. Downgrade с новыми административными данными
  и напоминаниями блокируется во избежание потери данных.

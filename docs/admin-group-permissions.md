# Права коллективов и Telegram-профили в админке

Это управление владельцами и администраторами **коллективов**. Глобальные права
бота и доступ к самой веб-админке не меняются.

## Как пользоваться

1. Откройте «Коллективы» → нужный коллектив.
2. В «Управление правами по @нику или Telegram ID» введите `@shigarovms` или ID.
   То же управление доступно у каждого подтверждённого участника в таблице.
3. Проверьте имя, профиль Telegram, постоянный ID и выбранный коллектив.
4. Для администратора: подтвердите чекбоксом и нажмите назначение / снятие прав.
5. Для владельца: откройте «Передать владение», проверьте обоих людей и введите
   точное название коллектива. Прежний владелец остаётся администратором, как прежде.

Назначение доступно только подтверждённым участникам выбранного коллектива.
Посторонний пользователь не добавляется в коллектив автоматически. Владельцу
нельзя снять права администратора; сначала требуется передача владения.

## Поиск по нику

Bot API не умеет искать произвольных людей по `@username`. Бот сохраняет ник,
переданный Telegram при сообщении, нажатии кнопки или добавлении бота в чат.
Неизвестному пользователю нужно открыть бота и отправить `/start`, затем пройти
регистрацию в коллективе. После обновления существующие пользователи появятся по
нику при следующем взаимодействии; поиск по ID доступен сразу.

Ник — изменяемая подпись, не ключ прав. В подтверждении показываются ID и время
последнего наблюдения ника. Если ник уже наблюдался у другого аккаунта, используется
последнее наблюдение; равные даты неоднозначны. После предпросмотра аккаунт ещё раз
сверяется, чтобы изменение или известная боту передача ника не выбрала другого человека.
Бот не узнаёт о смене ника без нового взаимодействия, поэтому перед назначением
нужно проверить человека по постоянному ID и профильной ссылке.

## Ссылки и безопасность

В пользователях, участниках, владельцах, поддержке, личных получателях очереди и
журнале действий есть ссылки на профиль. Стабильная ссылка `tg://user?id=...`
открывается Telegram-клиентом; при известном нике дополнительно доступна `https://t.me/...`.
Доступность профиля зависит от клиента и настроек Telegram. Внутренние карточки
пользователей в админке сохранены отдельно. Исходные тексты обращений не переписываются.

Все изменения выполняются существующими прикладными методами, с повторной проверкой
коллектива, участника, владельца и роли. Формы подписаны, одноразовые; режим просмотра
не допускает изменений. Действия и целевой пользователь записываются в аудит.
Личные черновики недоступны через управление ролями.

## Проверки и выпуск

Миграция `a82cd901be45` добавляет наблюдаемый ник и время наблюдения в `users`.
Не меняет владельцев, роли или прочие данные. Первая реализация — облачная песочница.
Серверная админка и её отдельная база обновляются позднее отдельным выпуском; новые
ники облачного тестового бота не синхронизируются в серверную базу автоматически.

```bash
TEST_DATABASE_URL=postgresql+asyncpg://setlist:setlist@localhost:5433/setlist_test \
  .venv/bin/pytest -q tests/test_admin_identity.py tests/test_admin.py \
  tests/test_admin_integration.py tests/test_migrations.py tests/test_support.py tests/test_telegram.py
```

Настоящие Telegram-сообщения эти тесты не отправляют. Перед обновлением бота
сделайте резервную копию его собственной тестовой базы, остановите только тестовый
polling, примените миграцию и запустите новый образ. Пароль админки не меняется.

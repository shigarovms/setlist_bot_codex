## 1. Тестовый контур

В консоли VPS:

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  git log -1 --oneline
  bash scripts/update-sandbox-admin.sh server
)
```

`test -z` останавливает процедуру при несохранённых изменениях исходников — сохраняйте
их отдельно, не выполняйте `git reset --hard`. Скрипт собирает образ, останавливает
только тестовые приложения, делает backup, применяет миграцию, выдаёт календарной
SQL-роли минимальные права и запускает тестовые сервисы после проверки health.
Существующий общий Caddy перечитывает маршруты с сохранением TLS-томов.
Основной polling и основная база не обновляются этим скриптом.

До обновления основной схемы её раздел в общей веб-админке может быть недоступен.
После обновления обоих контуров он снова проходит проверку совместимости.
Не запускайте второй экземпляр тестового polling в облаке.

Проверка базы и журнала:

```bash
cd /opt/setlist_bot_sandbox
docker compose -f compose.sandbox.yaml exec -T bot .venv/bin/setlist-bot --check
docker compose -f compose.sandbox.yaml logs --tail 30 bot
```

Ожидаются `PostgreSQL OK; migration a1426785384d` и polling тестового бота
с ID `1110437563`.

### Проверка с телефона

1. В группе отправьте `/concerts`, откройте сет-лист и вернитесь кнопкой
   «Назад к выступлениям»: «Мои коллективы» нигде не появляется.
2. В личке у пользователя с двумя коллективами `/concerts` и возврат из сет-листа
   по-прежнему предлагают «Мои коллективы» первой кнопкой.
3. Возьмите песню с пустым BPM/светом/комментарием. Импортируйте её с этими полями
   и другой длительностью. В предпросмотре должны быть только дополнения пустых
   полей; до подтверждения ничего не меняется.
4. Подтвердите: существующая песня дополнена, запись не продублирована, исходная
   длительность и заполненные поля сохранены. Повторный импорт ничего не дополняет.
5. Отмените другой импорт, проверьте сохранность каталога. Измените песню между
   предпросмотром и подтверждением: старое подтверждение должно отклониться.
6. Вставьте новые и уже известные песни одним пакетом; проверьте оба счётчика
   результата. Попробуйте также Article и одну песню в строке команды.
7. От обычного участника однострочное дополнение должно стать предложением
   администратору, без немедленного изменения каталога.
8. Если составы ещё не проверяли, пройдите сценарии приглашения/подмены из
   [инструкции модуля](staffing.md#проверка-с-телефона).

Открытые до обновления предпросмотры импорта лучше создать заново: их план
проверяется новым кодом перед сохранением.

## 2. Основной контур

После успешной проверки тестового бота выполните отдельно:

```bash
(
  set -e
  cd /opt/setlist_bot_codex
  test -z "$(git status --porcelain)"
  git switch main
  git pull --ff-only origin main
  git log -1 --oneline
  bash scripts/release-production.sh
)
```

Скрипт сначала собирает образы и репетирует миграцию на **новой временной копии
основной базы**, проверяя сохранение количества строк. До успеха этой проверки
основной бот продолжает работу. Затем останавливает основной bot/calendar/miniapp,
делает свежую копию, применяет миграцию к основной базе и проверяет сервисы перед
запуском polling. Копия не восстанавливается поверх рабочей базы.

Публичный календарь получает только чтение нужных полей назначений — без личной
занятости, предпочтений кандидатов или черновиков. SQL-роли и ключи разных контуров
не смешиваются. Тестовые данные в основной контур не импортируются.

```bash
cd /opt/setlist_bot_codex
docker compose exec -T bot .venv/bin/setlist-bot --check
docker compose ps
docker compose logs --tail 30 bot calendar miniapp
```

Ожидаются схема `a1426785384d`, основной polling ID `7430933141`, healthy у
calendar/miniapp. Проверьте прежние песни, выступления, PDF, календарные подписки
и работу редактора. Админка ждёт свежий runtime-сигнал совместимой основной версии;
он появится автоматически после запуска.

Если выпуск остановился с ошибкой, сохраните путь к backup и текст ошибки.
Не выполняйте downgrade или восстановление поверх основной базы: миграция составов
запрещает откат при наличии новых данных. Для диагностики достаточно ограниченного
журнала; `.env`, токены и дампы в чат не отправляются. Общий порядок восстановления:
[эксплуатация](operations.md).

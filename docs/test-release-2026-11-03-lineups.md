## Обновление на единственном VPS

Выполните в каталоге тестового контура, не основного:

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  git status --short
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  bash scripts/update-sandbox-admin.sh server
)
```

Перед переключением рабочее дерево должно быть чистым. Если есть изменения или
fast-forward невозможен, сохраните вывод и разберитесь с ним; не используйте
`reset --hard`. Скрипт собирает образ, останавливает только тестовые сервисы,
делает резервную копию **серверной тестовой базы**, применяет миграцию и проверяет
схему/здоровье. Он поднимает включённые тестовые admin/calendar/Mini App и polling.
Не запускайте в этот момент второй экземпляр тестового бота в облачной среде.

Проверка:


## Ручная проверка в Telegram

1. Зарегистрируйте новый тестовый коллектив. Проверьте предложение настроить основной
   состав, «Позже» и все прежние способы загрузки каталога. Введите роли с разными
   разделителями: `Вокал @ник`, `Гитара-@ник`, `Бас: 123456`, роль без исполнителя.
2. Укажите неизвестного боту человека. Перешлите отдельное приглашение. После его
   `/start` нажмите повтор: состав должен сохраниться без повторного ввода строк.
3. В `/groups` откройте «Составы [название]». Переименуйте, скопируйте состав,
   добавьте/удалите роль и удалите копию с подтверждением.
4. Создайте выступление при одном составе, затем при двух. Проверьте автоматический
   выбор, ручной выбор и строку `23.04 Клуб. Москва. 45 мин. Малый состав`.
   До нажатия отправки приглашений никто не должен получить приглашение.
5. Проверьте занятость, отправьте приглашения, отмените одно до истечения 42 секунд:
   этот человек не должен получить приглашение или отмену. Остальные получат его
   не раньше 42 секунд, подтвердят/откажутся в личке. Можно перезапустить только
   тестового бота в течение задержки: очередь должна сохраниться.
6. Откройте роль «ждём @ник»: проверьте напоминание и выбор другого исполнителя
   из знакомых/по @нику. Повторные нажатия не должны создавать пачку сообщений.
7. У подтверждённой роли стоит ✅. При подмене человек остаётся подтверждённым
   до согласия кандидата и одобрения администратора. Удалите роль с подтверждением:
   она исчезает, её участие отменяется. Удалите/измените сохранённый состав —
   уже созданное выступление от этого не меняется.
8. Откройте старые кнопки и попробуйте действия обычным участником/из другого чата:
   изменения не должны проходить. Проверьте новую `/set_no_concert_days` и `/help`.
9. В Mini App добавьте паузу, очистите её подпись, утвердите список и экспортируйте.
   Музыкантам — пустая строка без длительности; световику — длительность остаётся.
   Итоговое время не меняется. У стандартной и непустой подписи прежнее поведение.

## Откат

Не откатывайте схему вслепую: удалённые роли и выбранные составы защищены от потери.
При необходимости сначала остановите тестовые сервисы, сохраните новую резервную
копию и восстановите согласованную пару «образ + схема/база». Не подставляйте тестовый
дамп в основной контур. Основной выпуск согласуем отдельно после проверки.

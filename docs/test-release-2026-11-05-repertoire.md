## Обновление тестового контура на VPS

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  git status --short
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  bash scripts/update-sandbox-admin.sh server
)
```

Скрипт собирает образ, останавливает только тестовые сервисы, сохраняет резервную
копию серверной тестовой БД, проверяет схему и запускает admin/Mini App/calendar/bot.
Существующая SQL-роль Mini App получает только SELECT `song_aliases`; права записи
песен, алиасов и предложений ей не выдаются. Сохранение выполняет polling-бот.
Сети и конфигурация подключения админки к основному контуру сохраняются.

После завершения:

```bash
docker compose -f compose.sandbox.yaml exec -T bot .venv/bin/setlist-bot --check
docker compose -f compose.sandbox.yaml logs --tail 40 bot
docker logs --tail 20 setlist-sandbox-miniapp-1
```

Ожидается `PostgreSQL OK; migration d71f439e8a20` и polling @botToPract696_bot.
Закройте старый Mini App и откройте заново; `/groups`/`/catalog` получите заново,
чтобы проверить новые кнопки. Не запускайте второй polling с тем же токеном.

## Проверка с телефона

1. В личке `/groups` → коллектив: кнопки «Выступления», «Репертуар», «Составы».
   «Репертуар» открывает песни выбранного коллектива; чужие коллективы не раскрываются.
2. В `/catalog` справа у каждой песни нажмите «Редактировать». Измените BPM, свет,
   комментарий, название/длительность или добавьте альтернативное название через
   сообщения. Каталог остаётся; при выборе следующей песни переиспользуется карточка.
3. В Mini App добавьте одну песню дважды и паузу между ними. Карандаш у песни
   открывает форму всех полей. Измените название/длительность/свет/комментарий и
   алиасы: обе строки обновятся, порядок и пауза сохранятся. «Отмена» до отправки
   не меняет репертуар. Проверяйте отдельно администратором и обычным участником.
4. Внизу любой страницы репертуара «Добавить песню»: обязательны название и ММ:СС.
   Добавьте песню только с обязательными полями, затем с опциональными. Она доступна
   в репертуаре, но не попадает в черновик до отдельного выбора. Дубликат/неверная
   длительность не должны создавать запись.
5. Участник после сохранения получает сообщение о предложении. Репертуар меняется
   после решения администратора через `/proposals`. В предложении видны и алиасы;
   пустой набор очищает их только после одобрения.
6. Перетащите песню из репертуара прямо на нижний пунктирный «+ пауза»: песня
   добавится последней. Проверьте мышью/пальцем, повторы, прежние места вставки.
   Обычный тап по «+ пауза» по-прежнему открывает ввод паузы.
7. Откройте форму на двух устройствах. Сохраните на одном, затем на другом: второй
   запрос должен показать конфликт, сохранив введённые поля. «Загрузить актуальную»
   получает новые данные явно. Повтор сохранения после обрыва сети не создаёт копий.
8. Утверждённый ранее список сохраняет названия, длительности и порядок после правки
   репертуара. BPM/свет/комментарий в PDF световика по-прежнему берутся из каталога.

## Реализация и проверки

Формы используют существующий `Catalog.save`/`Catalog.decide`. Права и версии
проверяются при постановке в очередь и перед записью. Запрос и квитанция находятся
в существующих Confirmation/outbox; повтор неизменного request_id возвращает
прежний результат. Изменение песни и алиасов атомарно, ошибка откатывается savepoint.
Прекращение членства, архив песни, истёкшая сессия и удаление выступления закрывают
старый запрос. Квитанции удаляются вместе с выступлением при окончательной очистке.

Закрытие формы после отправки запроса уже не отменяет запись; при задержке доставки
кнопка называется «Закрыть», результат проверяется прежним запросом.

Целевые проверки: Mini App/API/мобильный Chromium, изолированная PostgreSQL-роль,
права и версии каталога, алиасы/одобрение, импорт, личные черновики/повторы/паузы,
история, навигация и сценарии обновления. Полный проект проверяется отдельно перед
выпуском основного контура. Реальный Telegram-клиент проверяется после установки.


Результат автоматической проверки: **172 целевых Python-теста и 9 JavaScript-тестов
прошли**, включая два мобильных браузерных сценария запуска (личка/группа).
Ruff, форматирование, mypy, синтаксис JS/shell и `git diff --check` успешны.
Использовалась только локальная `setlist_test`, Telegram — подменённый сеанс;
VPS не изменялся. Полный набор проекта на этом этапе не запускался.

# Основной выпуск: составы, уведомления и PDF — 3 ноября 2026

## Состав выпуска

Включает проверенные изменения после `8c0c914`:

- настройка основного и дополнительных составов, создание/копирование/изменение/
  удаление состава и ролей; автоматический выбор единственного состава при создании
  выступления, ручной выбор из нескольких и название состава в строке создания;
- неизвестному исполнителю — отдельное приглашение для пересылки и повтор ввода;
- полный текст ролей в составе выступления и сохранённом составе на всех страницах;
  кнопки отдельно по восемь, имена внутри коллектива и ✅ только у подтвердивших;
- контекстные уведомления администратору; назначение себя сразу учитывает согласие,
  занятость и согласование подмен продолжают проверяться;
- приглашения сразу через существующую очередь. В личной карточке участия — текущий
  общий сет-лист; экспорт только под утверждённым, личные черновики закрыты;
- `/set_no_concert_days` в меню/справке вместо `/busy`; старый ввод работает скрыто;
- пустой текст паузы в PDF музыкантов даёт пустую строку без длительности. Время
  учитывается в расчёте, PDF световика сохраняет длительность.

Оптимизация экрана состава: устранено повторное чтение прав после уже выполненной
проверки доступа под блокировкой; членство читается один раз для всего экрана.
Приглашения группируются по ролям одним проходом, подписи кнопок готовятся только для
видимой страницы. Сохранённые составы пакетно читают роли и исполнителей.
В контрольном замере отрисовки экрана состава выступления количество SELECT
уменьшилось с 13 до 10. Оно одинаково для одной и сорока ролей; у сохранённого состава
— 5 SELECT в обоих случаях. Это число чтений внутри отрисовки, а не замер пропускной
способности всего сервера. Лимит закреплён автоматическим тестом.
Права не кешируются, обработчики действий заново выполняют свою авторизацию.

## Схема и сохранность данных

`b63e2a71d940 → d71f439e8a20`. Миграция добавляет название/версию выбранного состава,
признак снятой роли и метки доставки/напоминания. Существующие роли, приглашения,
песни, выступления, черновики, утверждённые снимки и календарные ссылки сохраняются.
Удалённые роли хранят историю приглашений; редактирование сохранённого состава
не меняет уже созданные выступления. Откат схемы с новыми данными ограничен намеренно.

| Контур | Каталог VPS | База | Ветка |
| --- | --- | --- | --- |
| Тестовый | `/opt/setlist_bot_sandbox` | `setlist_sandbox` | `feature/web-admin` |
| Основной | `/opt/setlist_bot_codex` | `setlist` | `main` |

Публикация исходников в GitHub не обновляет VPS. `.env*`, токены, ключи, дампы и
тома PostgreSQL в выпуск не входят. Данные тестового бота в основную базу не
восстанавливаются. Новые домены, сервисы и настройки BotFather не нужны.

## Команда основного обновления

В консоли VPS выполните весь блок. При ошибке он остановится.

```bash
(
  set -e
  cd /opt/setlist_bot_codex
  git status --short
  test -z "$(git status --porcelain)"
  git switch main
  git pull --ff-only origin main
  git log -1 --oneline
  bash scripts/release-production.sh
)
```

Если есть локальные изменения или fast-forward невозможен, сохраните вывод и
разберитесь с ним. Не используйте `reset --hard` и не подставляйте тестовые дампы.

Скрипт проверит ID основного бота, соберёт образ, сделает резервную копию основной
базы и восстановит её **только во временную базу** `setlist_admin_release_*_test`.
Миграция там должна пройти без изменения количества записей приложения. До этого
основной бот продолжает работать. Только после успешной репетиции скрипт остановит
основные bot/calendar/Mini App, сделает свежую копию основной базы, применит миграцию,
выдаст прежним SQL-ролям необходимые точечные права и проверит HTTP-сервисы.
Polling запускается после успешных проверок. Произвольные ошибки не запускают
старую версию поверх непроверенной схемы; путь к резервной копии сохраните.

Тестовый бот остаётся отдельным работающим контуром. Основной раздел общей админки
станет совместимым с новой схемой; её код уже обновляется в тестовом каталоге.

## Проверка после обновления

```bash
cd /opt/setlist_bot_codex
docker compose exec -T bot .venv/bin/setlist-bot --check
docker compose ps
docker compose logs --tail 40 bot
```

Ожидается `PostgreSQL OK; migration d71f439e8a20` и polling `@setListDuration_bot`,
ID `7430933141`. Старые песни, выступления, варианты и ссылки календарей должны быть
на месте. В Mini App закройте старое окно и откройте заново.

Короткая проверка в основном боте:

1. `/start`, `/concerts`, открытие прежнего общего сет-листа, своего черновика и PDF.
2. `/groups` → коллектив → «Составы»: все роли видны при переключении кнопок.
3. Состав выступления: полный список, имена/✅ соответствуют подтверждённым участиям.
4. Назначение администратора себе — без личного подтверждения; приглашение другому
   человеку — с его ответом и контекстным уведомлением администратору.
5. Из личной карточки участия открывается текущий общий список. До утверждения нет
   экспорта; после утверждения он доступен под списком. Чужие черновики не видны.
6. Проверьте основной календарь, редактор и оба раздела общей админки.

Если обновление остановилось после выключения бота, не продолжайте вслепую:
сохраните журнал и путь backup. Восстановление кода и базы — согласованная пара по
[инструкции эксплуатации](operations.md); не выполняйте принудительный downgrade.

# Тестовый выпуск: подключение, участники и справочник ролей

Ветка `feature/web-admin`, схема `c91a72e6b304`. Обновляется только песочница
`/opt/setlist_bot_sandbox`. Основной бот и основная база не обновляются.

## Установка на VPS

Выполнить в консоли VPS, когда будет удобно переключить тестового бота:

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  bash scripts/update-sandbox-admin.sh server
)
```

Скрипт собирает образ, останавливает только сервисы песочницы на время обновления,
делает резервную копию **серверной тестовой базы**, применяет миграции, проверяет схему
и поднимает существующие сервисы. Том базы сохраняется. Данные из среды разработки
не копируются. Не используйте `down -v`, `pg_restore` или дамп из другой среды.

Админка с переключением контуров остаётся подключённой. Раздел основной базы может
показывать несовместимость схемы до отдельного обновления production; основной бот
от этого продолжает работать. Это не команда к обновлению production. При будущем
выпуске production нужно отдельно обновить ограниченные права его админки штатным
`connect-production-admin.py` в прежнем режиме просмотра/администрирования.

Проверка после скрипта:

```bash
docker compose -f compose.sandbox.yaml ps -a bot db
docker exec setlist-sandbox-bot-1 .venv/bin/setlist-bot --check
docker compose -f compose.sandbox.yaml logs --tail 40 bot
```

Ожидаются PostgreSQL OK, миграция `c91a72e6b304` и polling тестового бота.
Если тестовый polling ещё запущен где-то ещё, остановить его до серверного запуска.
Новый экземпляр в облачной среде для этого выпуска не запускается.

## Проверка с телефона и компьютера

1. Добавить тестового бота в **новый свободный чат**. Видна «🎸 Подключить коллектив».
   Нажать обычным участником, ввести имя. Создание может подтвердить только владелец
   Telegram-чата; инициатор получает права администратора коллектива. В уже привязанном
   чате новая регистрация не предлагается.
2. После создания появляется отдельное сообщение с принятыми участниками и кнопкой
   «Присоединиться к …». Обычный участник вводит несколько ролей, например
   `басист, гитарист`. Постороннее сообщение не должно превращаться в заявку.
   /cancel отменяет ввод. Администратор видит заявку также через /members.
3. До одобрения участника нет в постоянных исполнителях. После одобрения он появляется
   с обеими ролями, без прав администратора; сообщение списка обновляется на месте.
   Повторное одобрение не создаёт дублей. Для уже принятого человека отказ в заявке
   на роли не отменяет членство.
4. В «Участниках коллектива» изменить роль/приоритет или убрать постоянное назначение.
   Общий список отражает новые роли. В /profile поменять имя — обновляется имя в списке.
   Город/«о себе» в чат не попадают. Удалить сообщение списка вручную: следующая правка
   заменит его, без отправки в старый чат при переносе коллектива.
5. Открыть /groups в личке, в том числе пользователем без коллективов: первая кнопка
   «👤 Мой профиль». Команда /profile есть в личном меню; анкета прежняя.
6. Начать интернет-поиск репертуара и дойти до выбора исполнителя: только имя и
   «Песни коллектива:» с тремя песнями, без жанра. Отбор и импорт работают как прежде.
7. В админке тестового контура открыть «Профессиональные роли и синонимы», выбрать
   роль, добавить синоним. В профиле/подборе он распознаётся. Переименование сохраняет
   прежние навыки/назначения. Попытка присвоить синоним другой роли отклоняется;
   устаревшая форма просит обновление, повторная отправка не дублируется. В журнале
   действий есть запись. В режиме просмотра редактирование недоступно.

## Данные и ограничения

Миграция добавляет временные роли заявки/версию членства, справочник с начальным
словарём и привязку сообщения участников. Не меняет существующие песни, версии,
выступления, профили, приглашения и права. Старые коллективы получают сообщение
участников при первой новой заявке через /register; автоматической рассылки всем нет.
Введённые ранее роли не угадываются из старых имён участников.

Словарь общий в пределах одной базы, а не всех контуров. Старые синонимы сохраняются
для совместимости и не могут перейти к другой роли; удаления профессиональных ролей
в этом выпуске нет. Локальное название роли коллектива не переименовывается массово.
Список участников включает только принятые членства; добавление внешнего знакомого
само по себе не делает его участником коллектива.

Outbox переживает перезапуск. Как и у остальных отправок Telegram, при аварии между
успешным первым sendMessage и коммитом БД возможен повтор: Telegram не предоставляет
ключа идемпотентности. Обычные обновления используют сохранённые ID и editMessageText.
Ненужные промежуточные задания объединяются; чтение пользователей/ролей — пакетное.

Downgrade блокируется при заявках, сообщениях участников или изменённом словаре,
чтобы не потерять новые данные. Возврат после начала использования согласовывать
отдельно по резервной копии именно песочницы; не откатывать схему наугад.

## Исправление цикла перезапуска TelegramMigrateToChat

Симптомы: бот не доходит до polling, в журнале повторяются
`Command menu synchronization failed (TelegramMigrateToChat)`, контейнер постоянно
запускается заново и создаёт высокую нагрузку. Telegram сообщает новый ID группы,
преобразованной в супергруппу; старый запуск не обрабатывал этот ответ при проверке меню.

Сначала остановить **только тестового бота**, чтобы снять нагрузку:

```bash
docker stop setlist-sandbox-bot-1
```

Затем применить опубликованное исправление из `feature/web-admin` штатной командой
установки выше. Повторное применение миграций безопасно: новая версия схемы не добавлена,
остаются `c91a72e6b304` и серверная база. Полный скрипт сохраняет календарь/Mini App,
доступ к основной админке и настройки; не запускайте bot через один базовый compose-файл,
потеряв переменные существующих дополнительных конфигураций.

После запуска посмотреть **свежие** записи и нагрузку:

```bash
docker logs --since 3m --tail 60 setlist-sandbox-bot-1
docker stats --no-stream --format 'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}'
```

Ожидаются `Command menus verified`, `Start polling` и `Run polling ... @botToPract696_bot`.
Проверить /start и /concerts в существующей супергруппе. Если новый ID уже привязан
к другому коллективу, данные двух коллективов не объединяются автоматически.
Устаревшие личные контексты сами по себе больше не прерывают синхронизацию меню.
Если остаётся другая ошибка запуска, журнал покажет её класс и ожидание 30 секунд;
не обходите ограничения токена/базы/единственного экземпляра для ускорения запуска.

Исправление проверено **30 целевыми тестами**: миграция на каждом этапе API, старые
команды в новом чате, RU/EN/язык по умолчанию, области участников/администраторов,
отсутствие дублей, обновление привязки с сохранением владельца, недоступные чаты,
глобальные ошибки и задержка обычного старта. Ruff/форматирование/mypy проходят.

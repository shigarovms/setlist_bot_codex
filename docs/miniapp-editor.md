# Mini App личных черновиков — тестовый выпуск

HTML-редактор — основной способ ввода. «Предложить свой вариант» в группе и
«Изменить» в личке открывают Main Mini App сразу, без меню способов ввода.
Общая ссылка создаёт каждому участнику отдельную личную сессию; общий список не меняется.
При ограничении предложений администраторами редактор предлагает перейти к прежнему
сценарию запроса прав у владельца в Telegram. Старые способы сохранены как
[обратимо отключённые адаптеры](archive/setlist-input-methods.md).
Текущий выпуск: [установка и проверка](test-release-2026-11-01-editor.md).

## Как пользоваться

1. Добавляйте песни кнопкой `+` или перетаскивайте за ручку `⋮⋮` из репертуара
   в список. В каталоге поиск и страницы по 40 песен, сортировка по популярности.
2. Переставляйте за ручку; удаляйте крестиком у строки. Повторы сохраняются.
   Паузы прозрачные с пунктирной рамкой в обеих темах. Пауза добавляется отдельно:
   `3` — три минуты, `3 сек` / `00:00:03` — три секунды.
   Под списком также есть прозрачная кнопка «+ пауза» с пунктирной рамкой.
   В диалоге можно задать свой текст или оставить его пустым. Для изменения уже
   добавленной паузы нажмите на её текст или карандаш; длительность редактируется
   отдельно в том же диалоге. Отмена сохраняет прежние значения.
3. Ряд действий: «Отменить», «Сред. пауза», «+ Пауза». Средняя задаётся в секундах,
   включая 0. Администратор сохраняет её также как настройку **новых** сет-листов
   коллектива; участник меняет только свой черновик. Уже созданные списки,
   чужие черновики, отдельные паузы и история сохраняются.
4. Кнопка «← прошлые» сначала показывает непустые общие версии этого выступления,
   от последней к первой. Если их нет и общий список пуст, первым будет рекомендованный
   прошлый утверждённый список: тип важнее длительности, затем давность.
   Далее — прошлые утверждённые списки от свежих к старым, без повтора рекомендации.
   Вправо можно вернуться к текущему вводу. Просмотр ничего не заменяет;
   «Взять за основу» копирует список и его среднюю паузу. Данные песен берутся
   из актуального каталога; отсутствующие/архивные позиции требуют исправления.
   Чужие личные черновики в историю не попадают; порядок фиксирован на время сессии.
5. «Отменить» возвращает предыдущий шаг редактирования, включая среднюю (до 50 шагов).
6. Изменения автоматически сохраняются в **обычный личный черновик** после паузы
   около 1,2 секунды. Дождитесь «Сохранено» перед закрытием. Ручное сохранение тоже есть.
7. «📤 Предложить в группу и закрыть» сохраняет ввод, создаёт обычное предложение
   через существующую очередь бота и ждёт подтверждения доставки. Только после
   доставки окно закрывается. Это не применение к общему списку и не утверждение.
   При задержке можно повторно проверить отправку, без второй копии предложения.
   Закрытие крестиком и «Вернуться к боту» не публикуют предложение.

Сверху показаны текущая и запланированная длительности. Паузы не нумеруются;
при 10 и более песнях номера 01, 02… Тема меняется вместе с Telegram, без потери ввода.
Пока запрос сохранения не подтверждён сервером, ввод остаётся в открытом окне;
Telegram предупреждает о несохранённых изменениях при закрытии. При конфликте показывается актуальный черновик, свой ввод остаётся на
экране и его можно скопировать. Для продолжения загрузите актуальный вариант.
Удалённые/архивные песни не подменяются автоматически, интерфейс предложит их убрать.

## Установка на существующем VPS: только sandbox

Основной бот не обновляется. Рабочая ветка — `feature/web-admin`.
Календарный HTTPS уже должен работать на `212-192-217-128.sslip.io`, порты 80/443 открыты.
Для WebAppInfo-кнопки в личке отдельная настройка BotFather не нужна. Для прямого
запуска из группы включите Main Mini App у тестового бота в BotFather и задайте
URL `https://212-192-217-128.sslip.io/miniapp/`. Пользователь подтвердил эту настройку.
Для другого бота/домена настройка выполняется отдельно.

Выполните на сервере:

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  git log -2 --oneline
  bash scripts/update-sandbox-admin.sh server
  python3 scripts/setup-sandbox-miniapp.py
)
```

Первый скрипт собирает общий образ и сохраняет **собственную серверную тестовую БД**,
проверяет её схему и запускает тестовый контур. Установщик добавляет отдельный процесс
`miniapp` и ограниченную SQL-роль, проверяет HTTPS, затем включает кнопку в боте.
Если до этого календарный HTTPS ещё не настраивался, перед установщиком Mini App:

```bash
python3 scripts/setup-sandbox-calendar.py --host 212-192-217-128.sslip.io
```

Не запускайте параллельно облачный polling того же тестового бота. Базы между
контурами не копируются. Для Mini App новых таблиц нет. В текущем выпуске миграция
`f2d7c614a083` меняет default стиля сет-листа; данные между контурами не переносятся. Ранее запрошенные правки дат и меню — отдельный предшествующий коммит
`d1ec39d`, их откат Mini App не затрагивает.

Повторное обновление: `git pull --ff-only origin feature/web-admin`, затем
`bash scripts/update-sandbox-admin.sh server`. Наличие `.env.miniapp` включает сервис
в обновление автоматически. После смены токена **тестового** бота повторите
`python3 scripts/setup-sandbox-miniapp.py`, чтобы обновить производный ключ проверки.

## Устройство и ограничения

- `miniapp` — aiohttp на 8091, доступен только через маршрут `/miniapp/` в Caddy.
  Админка остаётся доступна через SSH-туннель; её HTTP-маршруты наружу не публикуются.
- Vanilla HTML/CSS/JS, без сборки фронтенда и сторонних UI-зависимостей.
- Сервер проверяет подпись Telegram initData, срок до часа, пользователя, членство,
  право предлагать варианты, неизменную цель сессии и версии черновика/каталога.
  Сессия кнопки действует 24 часа; после истечения авторизации откройте её заново.
- `.env.miniapp` имеет права 600, содержит отдельный пароль БД и производный ключ
  проверки initData. **Не публикуйте его**. Токен Bot API, ключ календарных ссылок
  и пароли админки в публичный процесс не передаются.
- SQL-разрешения: чтение данных редактора, создание/правка личного черновика,
  служебной сессии и запись аудита; при явной публикации — обычное предложение и outbox.
  Для ожидания доставки читаются только столбцы состояния очереди, не текст/payload
  других сообщений. Нет записи в общий сет-лист, каталог, утверждения и поддержку. Колонка id коллективов/участий доступна для UPDATE только ради
  `SELECT FOR UPDATE`; код редактора идентификаторы не изменяет.
  Из настроек коллектива разрешён UPDATE только `default_pause_seconds`; приложение
  дополнительно проверяет роль администратора. Установщик и скрипты обновления
  выдают это разрешение до запуска обновлённого сервиса.
- 192 MiB памяти, 0,75 CPU, пул 3 соединения, не более 4 одновременных API-запросов,
  до 200 позиций/5000 песен каталога. Локальные перетаскивания не обращаются к серверу.
- Сохранение вызывает `Setlists.edit_songs(private=True)`. Отдельной таблицы или
  независимой процедуры сохранения нет. Повтор отправки того же запроса не создаёт
  новую версию; устаревший ввод не перезаписывает черновик.

## Проверка после установки

1. В личке тестового бота откройте выступление → «Изменить» / «Предложить свой
   вариант»: сразу открывается редактор. Проверьте запуск из группы двумя участниками.
2. Добавьте одну песню дважды, ещё одну, паузу `3`; переставьте, удалите и отмените
   удаление. Проверьте порядок, повторы, длительность и отсутствие номера у паузы.
3. Проверьте среднюю 5 → 30 → 0 и отмену. Отлистайте общие версии и прошлые
   утверждённые выступления, вернитесь вправо: ввод остался.
   Снова откройте прошлое и нажмите «Взять за основу», внесите изменение.
4. Смените тему Telegram: список и изменения остаются, цвета обновляются.
5. Сохраните и вернитесь к боту: это личный черновик, в группе ничего не изменилось.
6. Откройте тот же черновик на другом устройстве, сохраните разные правки:
   второй устаревший запрос показывает конфликт и текущий вариант.
7. При включённом архивном флаге проверьте старые способы ввода; проверьте перенос даты с подтверждением года,
   «Мои коллективы» и возврат к выступлениям из подписки.

## Мобильный поиск и паузы — 3 ноября 2026

При новом входе в поиск прежний запрос очищается: можно сразу искать следующую
песню. Повторный тап внутри уже активного поля, изменение курсора и автосохранение
текст не очищают. При фокусе поле прокручивается к верху видимой области; положение
уточняется при изменении размеров экрана/клавиатуры. Это работает и с коротким каталогом.

Нажатие или жест вне поиска снимает с него фокус. Enter/«Готово» и Escape также
завершают ввод, сохраняя результаты до следующего входа в поле. Изменение размеров
страницы откладывается до окончания тапа, чтобы кнопка добавления не уехала из-под
пальца. Реальное скрытие системной клавиатуры нужно проверить в Telegram на iPhone
и Android; Chromium проверяет фокус и мобильную область просмотра.

Нижняя область удаления убрана; удаление доступно крестиком у каждой песни/паузы.
На её месте — «+ пауза» с прозрачным фоном и пунктирной рамкой. Она открывает тот
же диалог, что верхняя кнопка паузы. В просмотре прошлых списков добавление отключено.
Строки пауз прозрачные с пунктирной рамкой и в светлой, и в тёмной теме Telegram.
Кнопки истории одинаковой ширины, шрифт совпадает с подписью между ними.

Проверка на телефоне:

1. Найдите песню, нажмите `+`, затем снова войдите в поиск: поле пустое,
   результаты сброшены. Если нажать поле во время набора, текст остаётся.
2. Убедитесь, что поле находится сверху при открытой клавиатуре. Нажмите на песню,
   другую кнопку или область вне поля: клавиатура должна закрыться, действие выполниться.
3. Проверьте клавишу «Готово» и прокрутку списка, затем вновь откройте поиск.
4. Добавьте паузу нижней пунктирной кнопкой, удалите её крестиком, отмените удаление.
   Сравните фон паузы и песни в двух темах.
5. «← прошлые» открывает историю, возврат вправо сохраняет набранный черновик.

Изменения только в статическом интерфейсе; схема БД и API сохранения прежние.
Пройдены 24 целевые Python-проверки, включая два мобильных браузерных сценария,
и 7 JavaScript-тестов. Полный набор проекта для этой правки не запускался.
Публикуются в тестовую ветку `feature/web-admin`, основной контур отдельно не обновляется.
Для серверной песочницы используется штатная процедура:

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  bash scripts/update-sandbox-admin.sh server
)
```

После обновления полностью закройте Mini App и откройте редактор заново.

### Дополнение: подписи пауз

Описанный выше выпуск поиска был только интерфейсным. Следующее расширение
добавляет хранение текста паузы и требует миграцию `b63e2a71d940`.
Старые паузы получают стандартную подпись автоматически при отображении, без
изменения исторических снимков. Собственный текст и пустая подпись сохраняются
в черновиках, предложениях, утверждённых версиях и PDF.

После добавления паузы нажмите на подпись/карандаш: можно изменить текст или очистить
поле, затем «Применить». При пустой подписи остаются длительность, карандаш и удаление.
Убедитесь, что при закрытии без применения прежний текст не изменился.

Актуальный выпуск обоих контуров: [инструкция](release-2026-11-03-pauses.md).

Диагностика, не выводящая секреты:

```bash
docker inspect --format '{{.State.Status}} {{if .State.Health}}{{.State.Health.Status}}{{end}}' setlist-sandbox-miniapp-1
docker logs --tail 30 setlist-sandbox-miniapp-1
curl -fsS -o /dev/null -w '%{http_code}\n' https://212-192-217-128.sslip.io/miniapp/
```

Ожидается `running healthy` и HTTP 200. API без Telegram-авторизации должен
отказать; успешная загрузка HTML сама по себе не открывает данные.

Если сервис `miniapp` healthy, а установщик остановился сразу после запуска Caddy,
это этап проверки публичного HTTPS. Обновлённый установщик ждёт готовности и
отдельно сообщает HTTP-код, ошибку сертификата, DNS или таймаут. Для повторения
уже подготовленной установки пересборка и миграции не нужны:

```bash
git pull --ff-only origin feature/web-admin
python3 scripts/setup-sandbox-miniapp.py
```

Если HTTPS так и не готов, пришлите только код HTTP из curl и последние строки
`docker logs --tail 30 setlist-sandbox-calendar_proxy-1`; приватные env-файлы не нужны.

cd /opt/setlist_bot_sandbox

откройте свежее меню и используйте редактор в личке. При дальнейших зависимых
коммитах проверьте diff получившегося revert перед серверным обновлением.


## Репертуар в редакторе — 5 ноября 2026

Карандаш у песни открывает форму её полей в репертуаре коллектива: название,
ММ:СС, BPM, свет, комментарий и альтернативные названия (по одному на строку).
Внизу каждой страницы репертуара — «Добавить песню». Новая песня не включается
в черновик автоматически. Отмена формы до сохранения ничего не изменяет.

Администратор сохраняет напрямую, участник предлагает изменение; администратор
смотрит его через `/proposals`. В предложение входят и алиасы, в том числе их очистка.
История утверждённых списков остаётся неизменной. Все повторения изменённой песни
на текущем экране обновляются вместе; порядок, паузы и история отмены порядка сохраняются.

Сохранение выполняет существующий polling-воркер через outbox, без токена Telegram
и прав записи каталога у HTTP-сервиса. При недоступном воркере форма показывает очередь
и позволяет проверить тот же запрос. После явной отправки закрытие формы уже не отменяет
запрос. При конфликте можно загрузить текущие поля песни и повторить правку.
Обновлятор добавляет только SELECT song_aliases для существующей роли; схема не меняется.

Перенос из репертуара на всю нижнюю область «+ пауза» добавляет песню в конец списка.
Обычное нажатие по-прежнему открывает ввод паузы; прежние области вставки сохраняются.

## 1. Подготовить тестовый контур, оставив серверный polling остановленным

Тестовый бот первоначально работает в облаке Codex со своей местной базой.
Сначала на VPS:

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  test -z "$(git status --porcelain)"
  git pull --ff-only origin feature/web-admin
  git log -1 --oneline
  bash scripts/update-sandbox-admin.sh cloud
)
```

Скрипт проверяет ID токена и исходники, собирает образ, останавливает только
серверные тестовые bot/admin, сохраняет копию `setlist_sandbox`, применяет миграцию
и проверяет БД. Запускает admin и проверяет `/sandbox/healthz`. Уже настроенная
production-сеть, адреса БД и отчёт копий сохраняются; пароли и SQL-роль не меняются.
Основной bot/db скрипт не останавливает.

Нормальный результат: новая схема, admin работает, тестовый bot на VPS остановлен.
Передайте результат оператору облачной среды для переключения. Облачный polling
пока продолжает работать со своей независимой базой.

**Между обновлениями:** основной раздел нового admin временно сообщит о несовместимой
схеме до этапа 3. Основной Telegram-бот продолжает работать. Тестовые данные вместо
основных не показываются.

## 2. Переключить тестового бота на VPS и проверить

Оператор Codex сначала останавливает облачный polling и подтверждает остановку.
Нельзя запускать две копии одного токена, даже с разными базами. Затем на VPS:

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  docker compose -f compose.sandbox.yaml -f compose.admin.sandbox.yaml \
    -f compose.admin.production-access.yaml up -d --no-build --no-deps bot
  docker compose -f compose.sandbox.yaml exec -T bot .venv/bin/setlist-bot --check
  docker compose -f compose.sandbox.yaml ps -a bot
  docker compose -f compose.sandbox.yaml logs --tail 30 bot
)
```

Нужны `PostgreSQL OK; migration d89c3e17a024`, работающий контейнер и сообщение
`Run polling for bot @botToPract696_bot`. Первая синхронизация меню может занять время.

На телефоне откройте свежий `/concerts`, параметры выступления и `/catalog`.
Выберите несколько песен, проверьте сохранение каталога и замену карточки.
В `/add_new_songs` вставьте таблицу из Google Sheets ответом на запрос, проверьте
предпросмотр, уточнение столбцов и отмену. Проверьте набор личного черновика и PDF
своего утверждённого тестового списка. Сохраняйте только собственные тестовые данные.
Используются данные серверной песочницы: данные из облака туда не копируются.

## 3. Обновить основной бот после успешной серверной проверки

```bash
(
  set -e
  cd /opt/setlist_bot_codex
  test -z "$(git status --porcelain)"
  git pull --ff-only origin main
  git log -1 --oneline
  bash scripts/release-production.sh
)
```

Скрипт проверяет production ID, собирает образы, сохраняет основную базу и репетирует
миграцию на **новой временной копии этой же основной базы на VPS**. Тестовая БД
не используется. Только после успеха останавливает основной bot, делает свежую копию,
мигрирует настоящую `setlist`, проверяет её и запускает bot. В рабочую базу дамп
не восстанавливается, тома не удаляются и не пересоздаются.

При ошибке до остановки основной бот продолжает работать. При ошибке миграции
после остановки новый код не запускается. Сохраните вывод; не делайте автоматический
откат/восстановление поверх рабочей базы. Заполненный тип выступления защищает downgrade.
Проверьте `/start`, `/concerts`, свой каталог и утверждённый PDF у @setListDuration_bot.

## 4. Проверить оба раздела админки

Подождите около 30 секунд после старта основного бота для нового сигнала мониторинга.
Через прежний SSH-туннель откройте `http://127.0.0.1:8088`, проверьте оба контура.
Основной: ID 7430933141, production, новая ревизия и схема `d89c3e17a024`.
Тестовый: ID 1110437563, sandbox, location sandbox-server.

Проверка доступности с VPS, без вывода секретов:

```bash
cd /opt/setlist_bot_sandbox
docker compose -f compose.sandbox.yaml -f compose.admin.sandbox.yaml \
  -f compose.admin.production-access.yaml exec -T admin .venv/bin/python - <<'PY'
import json
from urllib.request import urlopen
for contour in ('sandbox', 'production'):
    with urlopen(f'http://127.0.0.1:8080/{contour}/healthz', timeout=5) as response:
        assert json.load(response).get('status') == 'ok'
    print(contour + ': OK')
PY
```

Повторная настройка `connect-production-admin.py` при обычном обновлении не нужна.
Если есть ошибка, смотрите логи admin; не меняйте владельца БД, пароль и конфигурацию
вслепую. При ручном пересоздании admin сохраняйте все три `-f`.

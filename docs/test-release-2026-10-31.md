## Что проверить

1. В личке `/groups` → коллектив: первая кнопка «Мероприятия [название]» открывает
   выступления этого коллектива. Ниже — перенос чата только для владельца.
2. Создайте отдельное тестовое выступление, откройте его в общем и личном чатах.
   Удалите с подтверждением. В сообщении результата и известных карточках остаются
   только поддержка и возврат к выступлениям. Обновление кнопок может занять несколько
   секунд через outbox. Текст сет-листа повторно не отправляется. Старые действия
   уже закрыты в момент удаления. Чужие/недоступные сообщения не редактируются;
   восстановление не позволяет запоздавшей задаче изменить новую карточку.
3. `/calendar` → подписка → «Показать ссылку»: повторный показ возвращает тот же URL,
   без подтверждения/перевыпуска. «Как подключить» содержит инструкцию и этот URL.
   Ссылку можно подключить на Mac, iPhone и передать близким для просмотра.
4. Для старой подписки без шифртекста: «Сохранить имеющуюся ссылку» → ответ на точный
   вопрос бота старым URL. Неподходящая ссылка даёт повтор ввода. Чужой пользователь
   не может ответить за владельца. Правильный ввод сохраняет ссылку без изменения
   хеша/версии и без отключения уже подписанных устройств. Если URL потерян,
   остаётся явный перевыпуск с подтверждением; автоматически он не выполняется.
5. У новой подписки имя по умолчанию `setListBot`. Если старое имя уже сохранено
   календарным приложением, его можно поменять вручную. Даты остаются на весь день.
6. Перевыпуск и отключение по-прежнему требуют подтверждения; отмена сохраняет
   рабочую ссылку. После перевыпуска показывается новый URL, предыдущий не обслуживается.

## Подготовленные команды VPS

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  git log -1 --oneline
  bash scripts/update-sandbox-admin.sh server
  python3 scripts/setup-sandbox-calendar.py --host 212-192-217-128.sslip.io
)
```

Штатный скрипт сохраняет собственную серверную тестовую базу, применяет c04f7a92d531
и пересоздаёт сервисы. Ключ `.env.calendar-key` генерируется один раз до подключения
Compose env-файла и затем сохраняется. Бот получает ключ, публичный calendar — нет.
Повторный установщик сужает SQL-доступ calendar до несекретных столбцов и сохраняет
существующие TLS-настройки/пароли. В базу добавляется только поле шифртекста.

**Сохраните частную резервную копию `.env.calendar-key` отдельно от дампа БД.**
При потере ключа и наличии шифртекстов установщик отказывается создавать другой;
нужно восстановить прежний файл. Это не отключает уже выданные календарные URL.
Не отправляйте ключ в чат, GitHub или публичный журнал.

Ожидаемая схема — `c04f7a92d531`, HTTPS — прежний 212-192-217-128.sslip.io.
Облачный polling остаётся остановленным. Тестовые данные в основной контур не копируются.
Основной раздел обновлённой админки потребует совместимой схемы production при
его отдельном выпуске; основной Telegram-бот продолжает работать.

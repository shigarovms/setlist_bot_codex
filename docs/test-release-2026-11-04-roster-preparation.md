## Обновление на VPS

```bash
(
  set -e
  cd /opt/setlist_bot_sandbox
  git status --short
  test -z "$(git status --porcelain)"
  git switch feature/web-admin
  git pull --ff-only origin feature/web-admin
  bash scripts/update-sandbox-admin.sh server
)
```

Скрипт сохраняет резервную копию серверной тестовой базы, собирает образ и проверяет
схему/сервисы. Данные облачной базы не переносятся. Основной контур не обновляется.

## Проверка с телефона

1. `/groups` → коллектив: «Выступления [название]» открывает расписание,
   «Составы [название]» — «Команда и составы». В нём только «Составы», «Знакомые
   исполнители» и «Назад» к коллективу. Вложенные разделы возвращаются к этому меню.
2. «Составы» → «Создать состав»: отдельно введите название («Основной», «Малый»,
   «DJ set», «С танцорами»), затем ответьте на новый запрос списком ролей/исполнителей.
   Посторонние ответы и повторный ответ на старое сообщение не создают второй состав.
3. Удаление сохранённой роли подписано «Удалить роль из состава», роли выступления —
   «Удалить роль из выступления». В свободной роли выступления — «пригласить/удалить».
4. Создайте выступление с составом. Обзор содержит роли и назначенных по умолчанию
   кандидатов под «Сейчас проверю занятость участников перед отправкой приглашений:».
   Внизу проверка/приглашение, «Изменить состав выступления» и «Назад».
5. Измените кандидата, удалите роль, добавьте новую. До подтверждения назначения в
   действующем составе не меняются, приглашения не приходят. «Назад» возвращает
   исходный список. Повторите изменения и нажмите «Подтвердить состав»: появляется
   обновлённый обзор, приглашений всё ещё нет. Сохранённый состав коллектива не меняется.
6. Проверьте занятость, вернитесь к редактированию, затем попробуйте старую кнопку
   отправки — она не должна сработать. Новая проверка и явная отправка приглашают
   только текущих кандидатов. Самоназначение администратора по-прежнему без личного
   подтверждения участия; другие исполнители отвечают сами.
7. «Назад» из обзора → выбор состава: выберите другой или «Выбрать состав позже».
   Выступление не дублируется. Вариант «позже» оставляет его без назначенного состава.
8. Укажите неизвестный @ник во временной правке: перешлите отдельное приглашение.
   После /start исполнителя повторите ввод кнопкой. «Назад» отменяет эту временную
   роль без добавления в живой состав. Попробуйте чужую и устаревшую кнопку.
9. `/all_my_concerts`: только предстоящие, прошлые — под «Прошедшие», по 20 на странице.
   Проверьте отдельные страницы архива и возврат. Выступления других коллективов
   видны только их участнику и только в личке; снятие доступа закрывает старые переходы.

## Проверки реализации

Сохранение подготовки атомарно и проверяет права, группу, состояние приглашений и
версию состава. Повторное подтверждение не создаёт повторных ролей; неизменённый
состав не перезаписывается. Смена даты, удаление и конкурентная правка закрывают
старую сессию. Блокировки людей при отправке берутся до блокировки коллектива.
Архив/предстоящие фильтруются в SQL до пагинации; наличие архива проверяется одной
строкой, без загрузки всех прошлых выступлений. Просмотр не создаёт личных черновиков.

Основной выпуск согласуется отдельно после проверки тестового бота.
